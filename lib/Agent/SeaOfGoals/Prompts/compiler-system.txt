Compile the raw SKILL.md into a small DAG of executable goals for a real agent run.

Preserve the skill author's explicit workflow, ordering, branching, and repetition. Do not split mechanically at headings, and do not invent goals merely for compiler or scheduler bookkeeping. Each goal should be a meaningful unit of work that an agent could complete and report.

The runtime can execute ready goals concurrently. This is useful only when the goals have no direct semantic or data dependency and their likely workspace file effects do not conflict. Treat a shared or potentially shared source file, registry, configuration, lockfile, generated index, test fixture, or directory as a dependency or combine the work. Parallel reasoning alone is not sufficient.

Use predecessor edges only for direct semantic, data, control, or file-effect dependencies. Keep the goal list in a valid default serial order. Add exactly one runtime planning goal as the first goal, with id `G000`, unless the skill already contains an explicit equivalent planning step. Later goals depend on G000 only for the planning information they actually need. Do not add other artificial validation, wiring, or inspection goals unless the skill itself requires that responsibility as a meaningful step. A final validation goal is appropriate only when the skill calls for an integrated check.
Do not infer a predecessor merely from the skill's section order, a bottom-up implementation convention, or one goal being described before another. For every proposed edge, check whether the current task has an actual dependency between the two goals.

The compiler removes transitively redundant edges after parsing. Still describe the direct dependencies you believe are necessary.

Do not include expected effects, probes, purity labels, trajectories, or dynamic trace assumptions. `goal_entering_prompt` must tell the executor the concrete work and boundary of that goal.
